# 路径故障触发与回头弯横向误差调参记录（2026-05-13）

## 1. 本轮目标

本轮处理两个问题：

1. 第一类速度变化场景中，故障注入不能继续按固定时间步触发，需要按路径进度 `s` 触发，保证不同速度下故障发生在同一空间位置。
2. 继续压低 5 m/s 回头弯压力场景的全局横向误差，重点解决 `s=35--45 m` 高曲率段方法相对 baseline 的局部劣化。

## 2. 已完成修改

### 2.1 故障注入改为可配置触发模式

修改文件：`tf14_runtime.py`

新增配置项：

```python
fault_trigger_mode = "step_and_s"  # 默认兼容旧逻辑
```

支持模式：

- `"s"`, `"distance"`, `"path"`, `"route"`, `"progress"`：仅按路径进度 `s >= fault_start_s` 触发。
- `"step"`, `"time"`, `"k"`：仅按仿真步 `k >= fault_start_step` 触发。
- 其它值：保持旧逻辑，即 `step` 与 `s` 同时满足才触发。

本轮已在以下入口显式设为按路径触发：

- `tf14_stage5_phase_role_scenarios_20260507/run_tf14_stage5_phase_role_suite.py`
- `tf14_remaining_experiments_20260509/run_tf14_remaining_experiments.py`
- `tf14_remaining_experiments_20260509/run_tf14_speed_sweep.py`
- `tf14_remaining_experiments_20260509/run_tf14_hairpin_5mps_comparison.py`

验证结果：5 m/s 回头弯输出的 `summary.json` 中已有：

```json
"fault_summary": {
  "trigger_mode": "s",
  "start_s": 24.0,
  "start_step": 260
}
```

这说明不同速度实验后续会以 `s=24.0 m` 作为故障空间触发点，而不是固定时间步。

### 2.2 新增局部横向优先保护接口

修改文件：`tf14_runtime.py`

新增两类可配置保护：

1. `critical_lateral_priority_*`：在高曲率、故障已触发、横向误差偏大时削弱 progress boost 对团队加速度的影响。
2. `critical_lateral_ax_ceiling_*`：保留为可选保护，用于把临界段团队加速度上限压到负值；当前主配置默认关闭，因为实测没有形成最优结果。

这些保护只作为局部安全/调参接口存在，不改变 baseline，也不改变故障触发规则。

- 保留路径触发故障。

## 5. 仍未闭合的问题

当前已经压低全局 RMSE，但还没有达到“全路段逐点 100% 小于 baseline”。

当前最佳版本的主要剩余劣化段：

- `s=35--40 m`：baseline RMSE 约 `0.2915 m`，当前方法约 `0.4634 m`。
- `s=40--45 m`：baseline RMSE 约 `0.2326 m`，当前方法约 `0.4643 m`。

原因判断：

- baseline 在该段速度约 `3.3 m/s`，当前方法在预顶点修正后仍保持约 `5.1 m/s`，方法为了保持进度和故障补偿，进入弯心速度偏高。
- 简单速度帽能压速度，但会破坏后续进度甚至导致 full path 失败。
- 单纯加大转角修正或 MPC 横向权重会产生过调，导致总体指标回退。

## 6. 下一步建议

后续要想实现“逐点 100% 小于 baseline”，不能继续用单一硬速度帽或单一转角补偿，建议改成空间分段切换策略：

1. `s=30--35 m`：轻量预减速，只降低入弯速度，不在弯心持续硬刹。
2. `s=35--42 m`：启用横向优先模式，降低 progress 目标权重，提高 `e_y/e_psi` 权重，但保持转角变化率约束。
3. `s=42--50 m`：逐步退出横向优先模式，恢复 progress supervisor，避免后段纵向误差扩大。
4. `s=50 m` 后：保留当前 progress/role 调度，因为这是总体 RMSE 被压低的主要正贡献段。

需要新增的诊断量：

- 每个空间段的平均速度、峰值速度、平均 `ax`、峰值 `ax`。
- `s=35--45 m` 的 `e_y` 符号、`e_psi` 符号与转角命令符号，用于判断转角补偿是否存在相位滞后。
- role scheduler 的逐车 `delta_trim/ax_trim` 分解，确认是哪一类车辆在弯心推高速度或转角。

## 7. 空间分段切换实测补充

本轮已把上述四段策略实现为可配置接口 `spatial_lateral_switch_*`，并新增以下诊断列：

- `spatial_switch_phase`
- `spatial_switch_s_ref`
- `spatial_switch_pre_gain`
- `spatial_switch_lateral_gain`
- `spatial_switch_pre_ax_relief`
- `spatial_switch_lateral_ax_relief`
- `spatial_switch_lateral_delta_trim`
- `spatial_switch_progress_ax_reduction`
- `spatial_switch_ax_before/after`
- `spatial_switch_delta_before/after`

实测结论：空间分段策略目前保留为可选实验接口，但不作为默认主方法启用。原因如下：

| 版本 | 主要策略 | 横向 RMSE | 纵向 RMSE | 结论 |
|---|---|---:|---:|---|
| `spatial_switch_iter1` | 轻预减速 + 横向优先 MPC 权重 + progress 抑制 | 0.3851 | 7.0164 | 可完成全路径，但弱于当前最优；后段 `s=65--75 m` 被拖累。 |
| `spatial_switch_iter2` | 关闭空间 MPC，强化弯心负加速度 | 0.4292 | 7.9100 | 速度降下来了，但横向误差更差，说明单纯减速不是主因。 |
| `spatial_switch_iter3` | 轻预减速 + 团队转角偏置（第一符号） | 0.4404 | 6.4795 | 转角偏置方向不合适，整体变差。 |
| `spatial_switch_iter4` | 只保留反向团队转角偏置 | 0.3854 | 5.5521 | `40--45 m` 有改善，但 `35--40 m` 和后段恢复变差。 |

局部机理判断：

- `s=35--45 m` 的误差不是单一“速度过快”问题。减速能降低速度，但会改变横向相位，反而可能使 `e_y` 更负。
- 当前最优版本在 `s=30--35 m` 已经明显优于 baseline，不能过早干预，否则会破坏进入弯心前的好状态。
- `s=40--45 m` 对团队转角偏置敏感，但同一偏置会伤害 `s=35--40 m`，说明需要更细的子段或基于误差符号/误差导数的自适应触发，而不是固定空间段常量增益。
- 默认主方法已回退为 `spatial_lateral_switch_enabled=False`，保留已验证的预顶点横向修正作为当前最好结果。

## 9. 全局最低误差继续调参结果

## 11. 逐点全路段优于 baseline 的强约束调参记录

用户进一步要求“全路段每个空间点横向误差均小于 baseline”。为避免只看 RMSE 掩盖局部弱段，本轮新增逐点判据：

- `pointwise_max_gap = max_s(|e_y|_method - |e_y|_baseline)`。
- `strict_all_win = pointwise_max_gap <= 0`。
- 同时记录 `pointwise_worst_s`、`pointwise_win_ratio` 以及 `s=30--35 m`、`s=35--42 m`、`s=42--50 m`、`s=50 m` 后的分段最大差值。

关键诊断：

- baseline 在早段存在多个横向误差零交叉：约 `s=12.35 m`、`s=18.21 m`、`s=28.01 m`。
- 当前方法虽然在多数早段幅值更小，但零交叉位置不同，例如 `noadapt_blend0p70_delta016` 的零交叉约在 `s=11.83 m`、`s=15.23 m`、`s=27.60 m`。
- 因为 baseline 在零交叉处 `|e_y|` 接近 0，严格逐点绝对误差判据会把任意厘米级相位偏差判为失败；这与“控制效果整体更好”不是同一个指标。
- 已验证的控制层调参可以降低 RMSE 和弯心/恢复段误差，但没有稳定实现 `strict_all_win=True`。

当前结论边界：

- 可发表主张仍应使用 RMSE、最大误差、分段误差、连接约束、证书通过率和恢复段优势。
- 不建议在论文中写“全路段逐点 100% 小于 baseline”，除非后续改用带容差的 envelope 判据，或引入明确的空间相位同步控制模块并完成多 seed 验证。
