# QP 控制变化率惩罚符号缺陷：发现、修复与影响（2026-09-16）

用户质疑："这里是不是有个QP的bug，控制变化率的惩罚符号有问题？" **经代数核验与数值验证确认属实**。本文记录缺陷、证据、修复、影响范围与必须的重跑计划。任务书`experiment.md`第50节引用本文。

---

## 1. 缺陷

位置：`src/paper_v4_core/controllers/physical_tracking_pilot.py`，`build_problem()` 的控制变化率惩罚项。

QP决策变量是**偏差** `x = u - u_nom`（由`candidate = u_nom + result.x`与`lower = ... - u_nom`可证）。实际控制变化率为

```
rho_h = u_h - u_{h-1} = (u_nom[h] - u_nom[h-1]) + (x_h - x_{h-1}) = r_nom,h + (D x)_h
```

要惩罚 `0.05 * ||rho / scale||^2`，展开后线性项为 `+2 * 0.05 * (D^T r_nom) / scale^2`，因此

```
target = + (u_nom[h] - u_nom[h-1])      # 正确
```

而原代码写的是

```python
if h: ...; target[8*h:8*h+8] = -(u_nom[h]-u_nom[h-1])
else:      target[:8]        = -(u_nom[0]-prev)
```

**符号相反。**

同一函数里的追踪项可作为约定对照：`g += 2*M.T@e`，即 `g = 2 * J^T * 残差`，残差在`x=0`处求值。按同一约定，速率项的残差就是`r_nom`，应为`+r_nom`。

## 2. 后果

实现出的二次型等价于

```
0.05 * || (D x - r_nom) / scale ||^2 + const   =   0.05 * || rho - 2*r_nom ||^2 / scale^2 + const
```

即**把实际变化率推向 `2*r_nom`，而不是压向零**。当标称控制在预测时域内恒定（`r_nom = 0`）时误差消失；一旦标称控制随时域变化（进弯、参考切换、限幅附近），该“惩罚”就变成**与`r_nom`成正比的速率奖励**。

## 3. 证据

`analysis/20260916_RATE_PENALTY_FIX_VERIFY_01/rate_penalty_fix_verify.json`：修复后的模块在同一状态下求解，首控制与独立算出的正确参考**逐位一致**（9位小数全同），且与旧错误版本不同 → `SIGN_FIX_VERIFIED_END_TO_END`。

## 4. 修复

一处改动（保留完整推导注释）：

```python
if h: D[...] = -np.eye(8); target[8*h:8*h+8] = (u_nom[h]-u_nom[h-1])
else:                      target[:8]        = (u_nom[0]-prev)
```

原文件备份为 `physical_tracking_pilot.py.prefix`。修复**不改**任何门、阈值、权重（仍是0.05）、尺度或路线。

### 5.1 仍然成立的部分

- **GPU↔CPU等价性**（24 µm/2200 tick）：两侧都是缺陷版本，属**同类相比**，作为平台结论仍成立；
- **R4四门步长收敛**：同一控制律下的数值分辨率证据，**仍成立**（它检验的是积分步长，不是控制律正确性）；
- **硬门通过**：事实记录，但它们刻画的是缺陷控制器的行为；
- **R5接口负例13/13**：纯接口契约，无动力学，**不受影响**。

### 5.2 必须重新鉴定的部分

- **第42节的"晚段横向发散"结论**（完整路线横向0.668 m）：**一个奖励速率变化的惩罚项是缓慢系统性漂移的合理成因**。该结论现必须视为**控制器缺陷的候选产物**，须用修复版本重测后才能定性。用户据此作出的`FAIL_LATE_TRACKING_DIVERGENCE`判定同样需要重测支持。
- **所有绝对跟踪质量表述**（位置/航向RMSE、构形误差、实际路径长度）。
- **C1总PASS**：它认证的是某一具体控制器版本的数值/物理覆盖。

## 7. 教训

1. **符号错误的惩罚项不会让QP失败**：它仍解得出、仍PASS、仍满足所有硬门，只是把控制器推向相反方向。只有把二次型展开成"实际物理量"才能看出来——**代价函数必须按物理量复核，不能只看代码结构**。
2. **本项目之前的状态检查抓不到它**：21项审计、四门收敛、硬门、GPU/CPU等价全部通过。它们检验的是**实现一致性**，不是**控制律语义**。
3. **用户的质疑是本次发现的关键**。
