## 根因：不是worker，是回包

第33节D2把阻断登记为“CPU端仍把NumPy ndarray放进pickle请求，worker反序列化时隐式导入NumPy”。本次用v4实测**否证**了它，并定位了真实原因：

1. worker自证显示`numpy`在**启动时**就在worker里（`forbidden_present_at_startup.numpy=true`，`imported_after_startup=[]`）——`import torch`自己会拉入NumPy，所以NumPy从来不是经请求反序列化进入worker的。
2. v4仍以`OMP Error #15`退出码3失败，说明请求路径的list化不解决问题。
3. 三进程隔离探针显示：父进程CPU链（numpy+scipy+osqp+植物）单独正常；worker单独跑`environment→rhs→rk4→rollout→linearize`全部正常并干净退出；torch单独跑CUDA float64 matmul正常。**没有任何单一组件会abort。**
4. 复刻资格脚本精确调用序列并开启`faulthandler`，抓到abort栈：

```
numpy.linalg.svd → internal_force._pinv → decompose_planar_point_forces
  → connector_diagnostics → assemble_derivative → system_derivative      (父进程)
```

5. 逐步计数显示：构造backend后父进程`torch`模块数仍为0，**调用`backend.environment()`之后变成718**。给`builtins.__import__`挂钩子后定位到入口是`torch.torch_version`。

**真实机制**：`torch.__version__`不是普通`str`，而是`torch.torch_version.TorchVersion`（str子类）。worker在环境回包里直接放了这个对象，pickle流因此带上`torch.torch_version`的**类引用**；父进程`pickle.loads`时被迫`import torch`，把torch的OpenMP运行库带进CPU父进程；父进程同时持有MKL的运行库，于是在下一次MKL LAPACK调用（`numpy.linalg.svd`）初始化`libomp.dll`时触发`OMP Error #15`并`abort()`。

这解释了v1/v2/v3“全都停在G1前”的历史：**G0自己的回包把炸弹埋进父进程，G1第一次真正调用`system_derivative`时引爆**。

## 两部分修复（第4轮）

1. `gpu_worker._plain()`：回包在pickle前递归强制为**精确内建原语**，str子类经编码/解码展平为精确`str`，遇到任何非原语直接抛`NON_PRIMITIVE_IN_IPC_REPLY`，不允许静默通过。
2. `ipc_backend._assert_parent_free_of_torch()`：父进程每次`pickle.loads`后断言没有新增torch模块，命中则抛`CUDA_PARENT_TORCH_CONTAMINATION`，把这类污染在发生的那一刻点出来，而不是在很后面的LAPACK调用处炸掉。

两部分都不改变任何数值：worker自证显示`imported_after_startup=[]`，`worker_boundary.clean`仍为false（numpy随torch在启动时进入worker），但**这不影响正确性**——worker里没有MKL，问题从来不是worker里有numpy，而是父进程里有torch。资格报告中的`interpretation`字段已如实记录：`clean=False`与PASS同时出现，正是对旧候选根因的否证。

## 边界（必须与结果同时引用）

- 本资格只覆盖**固定样本**：G1六类固定物理样本、G2两个固定QP用例。
- **不是**完整路线结论：没有跑2379周期闭环，4.32 s与5 s预算的对比是固定样本单次求解，不等于完整路线实时性。
- GPU只承担预测线性化；真实event-substep植物、QP组装、OSQP与非线性硬门仍在CPU。
- `PASS_PERFORMANCE`只支持“该固定样本上GPU路径更快且进入5 s预算”，不支持通信、分布式、Koopman优越性或材料安全结论。
- 资格脚本自身给出`next_action = STOP_NO_G3_G4; separate authorization and protocol required`。G3短窗、G4完整验证仍需**单独授权与单独冻结协议**，并且D3仍要求先补一次重启等价试验。
- 旧P1未续跑、未重跑，未拼接。
