# Koopman方法适用场景对比实验

> 日期：2026-08-22  
> 性质：预注册实验方案；2026-08-22细化并获授权执行  
> 目标：不预设某一种Koopman必然最好，在统一四车—货物模型上回答“哪一种方法更适合哪一种工况，以及其优势是否能传递到闭环控制”。

## 1. 实验要回答的问题

本轮不再以“证明双线性有效”为目标，而回答以下四个可证伪问题：

1. 在低激励、近线性工况下，复杂Koopman是否真的优于简单线性模型？
2. 在大转向、加减速、转向切换和连接器强受力阶段，输入—状态乘积是否使双线性Koopman获得稳定优势？
3. 神经lift、多步训练和多专家结构的收益分别来自哪里，是否只改善局部工况而损害总体或外推性能？
4. 离线预测误差的改善，能否在相同MPC中降低跟踪误差、四点连接力和货物拉伸载荷，并满足实时预算？

最终成果不是只给出一个总排名，而是输出一张“方法—工况适用图谱”。允许不存在全局最优模型。

## 2. 已知事实与待验证假设

### 2.1 已知事实

- 当前可部署基线为`M1 fixed S5-operational`。
- plant为30维四车—货物耦合模型，包含共同ICR转向和四点连接器。
- Koopman物理输入固定为46维`S3-deform`；四点力、货物拉伸载荷和力变化率只作为监督输出。
- 控制输入固定为8维`U1-four`，即四辆车实际施加的转向和纵向驱动输入。
- 受力输出为18维：四点`Fx/Fy`、`Q_FR/Q_LR`以及四点力的因果变化率。
- 历史旧31维DNN lift实验中，20步状态NRMSE为：linear `0.09594`、bilinear `0.17239`、bilinear+IRSP `0.19504`。这只能否定旧实现，不能替代新状态合同上的公平比较。
- 新合同上尚未重训完整双线性模型，因此目前不能断言“新线性一定优于新双线性”。

### 2.2 预注册假设

以下只是待验证假设，不作为预定结论：

| 方法 | 可能优势场景 | 主要风险 |
|---|---|---|
| raw linear | 直线匀速、低激励、数据较少、实时预算紧 | 非线性和长时域误差较大 |
| fixed lifted linear | 大部分正常工况；需要稳健、可复算的默认模型 | 不能显式表达强输入—状态乘积 |
| full bilinear | 大转向、大加减速、输入作用随状态明显变化 | 参数量大、输入共线、递推误差和过拟合 |
| structured bilinear | 存在少数明确物理输入模态的强耦合工况 | 结构选错会遗漏真实耦合 |
| trainable-lift linear | 固定二次基函数不足且训练数据充足的非线性工况 | seed敏感、外推差、解释性弱 |
| multi-step Koopman | 10–20步递推误差是主要问题时 | 可能牺牲一步精度、状态精度或实时性 |
| gated Koopman | 直线、转弯、过渡确有不同动力学且各专家均有足够数据时 | 专家塌缩、切换抖振、外推和稳定性问题 |

## 3. 统一实验合同

除明确标记的消融外，所有方法必须使用完全相同的合同：

```text
plant        = 已验收30维四车—货物耦合模型
state input  = S5-operational的46维S3-deform
control      = U1-four，8维实际施加输入
force output = 18维四点受力/货物拉伸载荷/因果力变化率
sample time  = controller 0.02 s，plant 0.002 s
rollout      = teacher-free 1–20步；40步只作长时域诊断
network vars = mask/AoI/quality只进入统一观测管理器，不进入物理lift或A矩阵
```

不得让某个模型独享未来状态、未来网络消息、不同参考轨迹、不同控制输入、不同归一化或不同异常轨迹清洗规则。

`Fy`指车辆平面内横向连接力，不解释为竖直支承力`Fz`。历史字段`opening`在代码中保留，论文和图中统一称为“货物拉伸载荷”。

## 4. 方法矩阵

### 4.1 第一阶段：只比较动力学算子

第一阶段所有模型共享同一个固定二次lift：

\[
\phi_0(x)=[1,x_{norm},\operatorname{clip}(x_{norm},-8,8)^2]\in\mathbb{R}^{93}.
\]

这样能够把差异归因于算子，而不是同时改变状态、lift和训练目标。

#### K0：raw-state linear

\[
x_{k+1}=A_xx_k+B_xu_k.
\]

作用：给出最低复杂度、最强解释性和最快计算基线。

#### K1：fixed lifted linear

\[
z_{k+1}=Az_k+Bu_k.
\]

作用：当前默认基线；检验固定二次lift是否已经吸收主要非线性。

#### K2：full bilinear

\[
z_{k+1}=Az_k+Bu_k+\sum_{j=1}^{8}u_{k,j}N_jz_k.
\]

作用：直接检验8个实际车辆输入与lifted state的乘积是否有价值。

93维lift和8维输入下，K1转移参数为`9,393`个。由于`z_0=1`，K2的双线性项必须只作用于`z[1:]`，否则`u_jz_0`与`Bu`完全重复并必然造成秩亏；去重后的K2独立转移参数为`77,841`个。必须同时报告参数量、回归矩阵条件数和有效秩，不能把增加容量自动解释为结构优势。

#### K3：structured/low-rank bilinear

\[
z_{k+1}=Az_k+Bu_k+\sum_{q=1}^{n_m}\eta_{k,q}L_qR_q^Tz_k.
\]

其中`eta`不是任意新的控制输入，而是从8维实际输入中得到的物理模态：

- 共同纵向驱动；
- 前后纵向差动；
- 左右纵向差动；
- 对角纵向差动；
- 共同曲率/转向模态；
- 只有在不破坏共同ICR时才允许加入转向残差模态。

输入模态变换只用train数据或已知分配矩阵确定，不能查看test后调整。候选秩固定为`r={2,4,8,12}`，只在validation选择。

除validation最优秩外，再固定报告一个“参数量匹配K3”：使其转移参数量控制在K1的`±20%`以内。该对照用于判断收益来自物理双线性结构，还是仅来自更多自由参数。

K3的作用是区分：“双线性思想无效”还是“完整8输入双线性因参数过多和共线而无效”。

### 4.2 第二阶段：分别检验其他机制

只有第一阶段完成后才执行，避免同时改变多个因素。

#### K4：trainable-lift linear

- 保留原始46维状态的恒等嵌入；
- 学习特征数固定为46，使总lift维数与固定lift同为93；
- decoder、训练数据和输出任务与K1一致；
- 至少5个训练seed，报告中位数、最差seed和离散程度。

比较`K4 vs K1`只回答“可训练lift是否优于固定lift”，不讨论双线性。

#### K5：multi-step版本

分别对第一阶段最优线性模型和最优双线性模型加入相同的1–20步损失：

\[
L=L_{1step}+\lambda_rL_{rollout}+\lambda_fL_{force}+\lambda_qL_{load}.
\]

所有权重在validation前预先冻结。比较`one-step vs multi-step`只回答“训练目标是否改善长时域”，不能把结果归因于算子结构。

#### K6：gated/residual expert

只有满足以下前置条件才允许执行：

1. 分工况oracle模型相对global模型至少存在10%的可利用差距；
2. 直线、转弯、过渡每类训练样本均足够；
3. global模型残差在至少两个工况中呈现方向稳定的结构差异。

优先采用“共享global + 受限专家残差”，不重新使用三个完全独立专家。若前置条件不满足，K6记为“不适用”，不继续调门控参数。

### 4.3 IRSP的位置

IRSP不进入预测精度主排名。只有某一bilinear模型先在独立test证明预测和闭环优势后，才单独研究连续输入域证书。

有限采样谱半径小于1不能作为连续输入域稳定性证明；IRSP投影前后必须分别报告预测误差、二范数界、非正规性和闭环可行率。

## 5. 工况与优势场景设计

每条轨迹同时具有“场景标签”和“瞬时动力学标签”。瞬时阈值只由train统计确定，冻结后用于validation/test/confirm。

| 编号 | 场景 | 主要激励 | 重点判断 |
|---|---|---|---|
| E0 | 直线匀速 | 低转向、低加速度 | raw/fixed linear是否已经足够 |
| E1 | 直线加速—匀速—制动 | 纵向输入和前后拉伸载荷 | 双线性是否改善输入随速度变化的纵向作用 |
| E2 | 不同半径稳态左/右弯 | 持续曲率、横摆和横向连接力 | bilinear是否改善稳态输入—状态耦合 |
| E3 | 正反阶跃转向 | 转向进入、保持和反向切换 | multi-step或过渡专家是否减少瞬态误差 |
| E4 | 单移线 | 横纵向耦合、曲率换向 | 综合正常操纵性能 |
| E5 | 回头弯 | 大曲率、持续横摆和高侧向力 | bilinear/learned lift的强非线性优势 |
| E6 | 连接器方向激励 | 前后/左右/对角差动力 | 四点力方向、货物拉伸载荷和结构bilinear |
| E7 | 参数外推 | 货物质量、连接刚度/阻尼/间隙、轮胎附着变化 | learned lift或复杂模型是否真正泛化 |
| E8 | 网络退化 | delay、dropout、burst、DoS | 同一观测管理器下的模型鲁棒性；不把网络变量混成物理状态 |
| E9 | 可辨识性激励 | 物理可行multisine/PRBS输入模态 | 判断bilinear失败是否来自输入共线和激励不足 |

### E9输入约束

- 转向激励通过共同曲率命令产生，再由已验收分配器转换为四车实际转角；不得独立随机四车转角破坏共同ICR。
- 纵向激励包含共同、前后差动、左右差动和对角差动，但差动分量保持零和，幅值不超过当前已验收控制包络。
- 频率和幅值从train中预注册的分位数组合产生，覆盖低、中、高三档，不根据test误差补数据。
- 每条轨迹持续检查轮胎利用率、共同ICR残差、四点力、货物拉伸载荷和数值有限性；触发plant验收上限即停止该轨迹并保留失败记录，不静默删除。

## 6. 数据划分与防泄漏

### 6.1 开发数据

继续使用现有120条轨迹作为development数据：

```text
train / validation / development-test / external = 70 / 15 / 15 / 20
```

现有test和external已经被多轮开发查看，因此只能称为development证据，不能作为最终确认集。

### 6.2 新确认集

所有方法、超参数、阈值和图表代码冻结后，再生成且只查看一次：

- 100条internal-confirm：覆盖E0–E6，场景均衡；
- 40条external-confirm：参数组合、网络trace和初始条件不与开发集重复；
- confirm的seed和hash在生成前写入manifest；
- confirm不用于归一化、正则化、rank、epoch、门控阈值或模型选择。

如果执行中提前查看confirm来调参，本轮confirm立即失效，必须重新预注册新的seed集合。

### 6.3 数据量学习曲线

使用按场景分层、互相嵌套的`10%/25%/50%/100%` train轨迹训练K0–K4，validation和test保持不变。每一档至少重复5个轨迹子集seed，报告误差—数据量曲线。该实验用于区分：

- 简单模型在小数据下的样本效率优势；
- full bilinear是否只有在数据充分时才开始获益；
- trainable lift的改善是否依赖过大的训练集；
- 某模型是否随着数据增加仍无改善，说明问题更可能来自结构或可辨识性，而不是样本量。

## 7. 训练公平性与辨识审计

### 7.1 训练前审计

在训练双线性模型前必须输出：

- 8维U1的相关系数、奇异值和有效秩；
- full bilinear特征`[z,u,u_1z,...,u_8z]`的条件数和有效秩；
- 各输入模态在E0–E9中的覆盖范围；
- 各工况样本量与20步窗口数；
- 连接器未接触、接触和强受力阶段的样本比例。

所有特征先使用train统计归一化。有效秩定义为满足`singular_value / max_singular_value >= 1e-8`的奇异值数量；秩比例为有效秩除以回归特征列数。

若full bilinear特征条件数超过`1e8`或有效秩比例不足90%，K2结果必须标记为“不可可靠辨识”，不能解释为双线性机理无效；此时继续K3和E9，但不通过放宽test规则挽救K2。

### 7.2 统一调参规则

- 所有归一化只由train计算。
- ridge候选固定为`10^{-8}`至`10^{-1}`的对数网格。
- 神经模型最多80 epoch、batch 256、梯度裁剪1.0；early stopping只看validation。
- 随机训练模型固定5个seed；不只报告最好seed。
- validation采用场景等权macro指标，避免样本最多的直线工况主导选择。
- 一旦进入development-test，不再更改特征、rank、正则化、损失权重或停止阈值。

## 8. 评价指标

### 8.1 离线预测

所有模型报告第`1/5/10/20`步以及`10–20`步平均：

1. 四车状态NRMSE：`vx/vy/yaw/yaw-rate`分组；
2. 货物状态NRMSE：平动、横摆、横摆角速度；
3. 四点连接形变与相对速度NRMSE；
4. 四点`Fx/Fy`的NRMSE、峰值误差和方向符号准确率；
5. `Q_FR/Q_LR`的NRMSE、峰值误差和受拉方向判断准确率；
6. 力变化率误差、峰值时刻误差；
7. 误差随预测步增长斜率、非有限率和发散率。

主要综合指标固定为：

\[
J_{pred}=\frac{J_{state}+J_{connector\ force}+J_{cargo\ load}}{3},
\]

其中三项先在各场景内计算，再对E0–E9等权平均。不能用综合指标掩盖单个安全相关变量恶化。

### 8.2 双线性是否真正起作用

对K2/K3额外计算：

\[
r_{bil}(k)=\frac{\|\sum_j u_{k,j}N_jz_k\|_2}
{\|Az_k+Bu_k\|_2+\epsilon}.
\]

并执行三个消融：

1. 预测时将bilinear项置零；
2. 在轨迹内打乱`u-z`配对但保持边缘分布；
3. 保留相同参数量但打乱物理输入模态。

只有bilinear项在目标工况贡献非零、置零后性能显著下降、正确配对优于打乱配对，才能说明模型实际利用了输入—状态耦合。

### 8.3 物理一致性

- 四点作用—反作用合力残差；
- 预测货物合力/合力矩与货物加速度、横摆加速度的一致性；
- 左右、前后拉伸载荷方向是否与四点力方向一致；
- 转向换向前后横向力符号和峰值时刻是否正确；
- 高误差是否集中在连接间隙接触/脱离瞬间。

### 8.4 计算代价

- 参数量、模型文件大小和训练时间；
- 单步及20步rollout的mean/p95/p99时间；
- MPC整步求解p95/p99时间和超时率；
- 显存/内存占用。

控制周期为20 ms，闭环MPC的p99不得超过20 ms；超时必须计为失败，不能删除。

### 8.5 闭环价值

只有离线门通过的模型进入相同MPC。固定控制权重、约束、时域、求解器、参考轨迹、观测管理器和seed，比较：

- 横向/航向/速度跟踪误差；
- 四车横摆与系统横摆；
- 四点连接力峰值、RMS和高载荷持续时间；
- `Q_FR/Q_LR`峰值、RMS和方向判断；
- MPC不可行率、fallback次数、完成率和运行时间；
- clean、单移线、回头弯、通讯扰动和DoS下的性能变化。

离线预测改善但闭环无改善时，只能报告“预测模型优势”，不能声称控制收益来自该Koopman。

## 9. 统计与优势判定

- 以整条轨迹为统计单位，使用2000次paired bootstrap计算95% CI。
- 多模型比较使用Holm校正；同时报告绝对差、相对差和CI，不只给`p`值。
- 同时报告场景等权macro结果和自然频率micro结果；模型选择以macro为主。
- 神经模型报告5个seed的中位数、四分位范围和最差seed。

某方法只有同时满足以下条件，才能标记为某场景的“优势方法”：

1. 相对该场景最佳简单基线，`J_pred`改善至少8%；
2. paired 95% CI不跨0；
3. 任一关键状态或受力分组不得恶化超过5%；
4. 非有限率、发散率和峰值方向错误率不增加；
5. 满足20 ms闭环实时门；
6. confirm结果与development-test方向一致。

若差异小于3%且CI跨0，结论写为“性能等价”，此时优先参数更少、计算更快、解释更清楚的模型。

```text
T0 冻结
├─ 冻结plant、S5/U1、数据hash、指标、seed和图表模板
└─ 记录当前K1模型与历史负结果

T1 可辨识性审计
├─ U1输入秩/相关性
├─ full bilinear特征条件数/有效秩
├─ 工况与连接接触覆盖率
└─ G1：不可辨识则K2只作诊断，转K3+E9；不得宣称双线性无效

T2 固定lift算子比较
├─ K0 raw linear
├─ K1 fixed lifted linear
├─ K2 full bilinear
├─ K3 structured/low-rank bilinear
└─ G2：独立development-test优势与bilinear贡献消融

T3 机制分离实验
├─ K4 trainable lift vs K1
├─ K5 one-step vs multi-step
├─ oracle residual工况审计
└─ G3：oracle gap不足则不训练K6；多步/神经失败即冻结负结果

T4 新confirm
├─ 冻结全部模型和代码hash
├─ 生成100 internal + 40 external
└─ G4：只查看一次；未复现则取消相应优势主张

T5 相同MPC闭环
├─ 正常单移线
├─ 正常回头弯
├─ 通讯扰动
```

## 12. 最终结论模板

最终报告按证据选择下列一种或多种表述，而不是预先认定双线性优越：

- **若K1全局最好**：完整物理状态和实际四车输入使固定lifted linear已足够；复杂模型没有获得与成本相称的收益。
- **若K2只在E2/E5有效**：完整双线性适合持续大曲率强输入—状态耦合，但不适合作为所有工况的默认模型。
- **若K3优于K2**：双线性机理有价值，但应使用物理输入模态和低秩结构，完整8输入展开存在共线和方差问题。
- **若K4只在E7有效**：可训练lift适合数据充足的强非线性/参数变化场景，但正常域不值得增加复杂度。
- **若K5只改善10–20步**：多步训练适合预测时域较长的控制器，但需单独证明实时闭环价值。
- **若K6只改善E3**：门控只作为过渡残差修正，不升级为全局三专家模型。
- **若没有方法稳定胜出**：选择K1作为默认模型，并如实报告复杂Koopman在本场景中未显示稳定优势。

局部优势不自动授权在线模型切换。若最终需要按工况切换模型，还必须另行验证切换器的因果性、最短驻留、抖振、fallback和闭环稳定边界。

### 13.2 E0–E9标签的可复算定义

以20步rolling-origin窗口为评价单元，统计推断仍以整条轨迹为单位。标签允许重叠，因为E7/E8是压力标签，E0–E6是物理操纵标签。

- `E0`：`staged_100m`中低转向、低加速度、低转向变化窗口。
- `E1`：`staged_100m`中低转向且加速度超过低激励阈值的窗口。
- `E2`：`hairpin`中转向幅值位于train非零转向`50%–80%`分位且转向变化低于高变化阈值的持续弯窗口。
- `E3`：`staged_100m`中20步窗内发生转向符号改变，或转向变化超过train非零变化量90%分位的窗口。
- `E4/E5/E6`：分别为`single_lane_change/hairpin/connector_directional`整条轨迹的窗口。
- `E7`：全部`development-external`轨迹的覆盖标签，同时保留其原E0–E6物理标签。
- `E8`：`network_excitation`轨迹的窗口；网络列只供观测管理和分组，不进入物理lift。
- `E9`：按第5节约束新生成的共同曲率加四个纵向模态multisine/PRBS轨迹。

低激励阈值取train非零绝对值25%分位，持续弯中位/高位阈值取50%/80%分位，高变化阈值取非零一阶差分90%分位。算法现在冻结，具体数值由T0只读train后写入`labels.json`，之后不再修改。

validation选择只使用其实际存在的E0–E6/E8标签与E9-validation；E7不参与选择。最终development macro由E0–E6的development-test、E7的development-external、E8的development-test和E9-development-test等权组成。

### 13.3 K0–K3精确定义

- `K0/K1`主排名直接加载并复算现有`S3-U1-raw.npz`和`S3-U1-lifted.npz`，确保当前M1基线不因本轮调参被改写。
- K2使用
  
  \[
  z_{k+1}=Az_k+Bu_k+\sum_{j=1}^{8}u_{k,j}N_jz_{k,1:}.
  \]
  
  回归列数为`93+8+8×92=837`，独立转移参数为`837×93=77,841`。
- K3固定五个物理模态，车辆顺序为`FL/FR/RL/RR`：共同纵向、前后纵向差动、左右纵向差动、对角纵向差动、`(δ_FL+δ_FR-δ_RL-δ_RR)/4`共同曲率转向。主实验不加入转向残差模态。
- 模态只由已知车辆布局矩阵确定，再用train均值/标准差归一化；不得用development-test修改。
- K3先在每个ridge下拟合无约束五模态结构算子，对每个模态块作SVD截断到`r={2,4,8,12}`，随后固定低秩块，只在train重拟合`A/B`。validation按场景等权`J_pred`选择ridge/rank。
- K3低秩参数量为`9,393+5×r×(93+92)`；参数匹配对照固定为`r=2`，共`11,243`个，较K1增加`19.70%`，满足`±20%`门。
- ridge网格精确为`{1e-8,1e-7,…,1e-1}`。K2/K3先最小化validation macro `J_pred`；差异小于`1e-6`时依次选择参数更少、ridge更大的候选。
- K2/K3的`bilinear置零`、轨迹内`u-z`循环打乱、物理模态列固定置换三种消融均使用冻结模型，不重新训练；置换偏移由轨迹ID和seed确定。

### 13.4 K4–K6精确定义

- K4 lift固定为`[1,x_norm,gθ(x_norm)]`，其中`gθ:46→64→46`、GELU、保留46维恒等嵌入，总维数93。优化器AdamW，`lr=5e-4`、`weight_decay=1e-6`、batch 256、最多80 epoch、梯度裁剪1.0、patience 10、`min_delta=1e-5`。
- K4训练seed固定为`82041–82045`。主比较报告五seed中位数/IQR/最差seed；进入confirm和闭环的代表模型固定为validation macro最接近五seed中位数者，不选择最好seed。
- K5分别作用于T2中validation最优的K0/K1线性算子和K2/K3双线性算子。归一化后的状态、四点连接力和`Q_FR/Q_LR`各自先取组内均值，冻结`lambda_r=lambda_f=lambda_q=1`；训练seed为`82301–82305`，其余预算与K4相同。
- K6 oracle类别固定为：直线=`E0/E1`，持续弯=`E2/E5`，过渡=`E3/E4`；E6/E8使用global，不单设专家。每类至少10条train轨迹且至少2000个20步窗。
- oracle gap在validation上按类计算；至少两类相对global改善10%，且各类残差在按轨迹奇偶划分的两半中均值方向余弦大于0.7，才允许K6。K6只拟合`global+限幅残差`，残差步长范数不超过global预测步长的20%。不满足则写`not_applicable`。

### 13.5 学习曲线、统计和计时

- 嵌套分层子集seed固定为`82101–82105`。每个seed在每个物理场景内只生成一次轨迹排列，`10/25/50/100%`取其嵌套前缀。
- K0–K3在各档使用T2已冻结的结构/rank/ridge；K4将五个子集seed与五个训练seed一一配对，因此每档每方法恰有5次，不额外挑最好组合。
- paired bootstrap固定2000次；每个指标seed由`SHA256("82200|场景|指标")`确定。Holm校正的模型集合在查看development-test前冻结。
- 推理计时先warm-up 100次，再测1000次；报告单步和20步的mean/p95/p99。内存包含模型常驻与一次batch=1工作区，不把数据集缓存计入模型内存。

### 13.6 E9、confirm和闭环seed

- E9 seed固定为`83000–83023`，按`14 train/3 validation/3 development-test/4 external`顺序分配。幅值/频率只取原70条train对应模态绝对值的`50%/80%/95%`分位，零和差动和共同ICR门保持不变。
- confirm internal seed固定为`84000–84099`：E0/E1/E2/E4/E5各14条，E3/E6各15条，共100条。
- confirm external seed固定为`84100–84139`：20条E7参数组合外推、20条E8网络trace外推，底层E0–E6按seed循环均衡。
- 生成前冻结seed清单、生成器hash、配置hash和全部模型hash；轨迹内容hash不可能在生成前得知，故在每条生成完成后立即写入只读manifest，并在任何指标计算前二次校验。这是对第6.2节“生成前写hash”的可实现性修正。
- confirm只运行冻结模型；不重选ridge/rank/seed/epoch/门。任一文件在指标查看后变化，confirm整批失效。
- 闭环配对seed固定为`85001–85010`。K0/K1作为简单基线始终运行；候选模型只有在G4至少一个场景满足第9节优势门时才进入相同MPC。若无候选，T5记录为`not_applicable_no_offline_candidate`，不得为了生成闭环图降低门槛。
- 相同MPC冻结预测时域20步、控制周期20 ms、控制权重、约束、求解器、观测管理器和候选输入集合；任何模型p99超过20 ms均记实时门失败，不删除超时步。
